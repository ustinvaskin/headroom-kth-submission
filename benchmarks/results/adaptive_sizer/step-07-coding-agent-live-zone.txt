ADAPTIVE SIZER EXPERIMENT - STEP 7
Date: 2026-09-02
Source: Captured from terminal output during the experiment.

GOAL
Measure the accepted ASCII SimHash fast path through a real coding-agent production route rather than an internal SimHash function.

PRODUCTION ROUTE
compress_anthropic_live_zone
  -> JSON tool_result detection
  -> SmartCrusher::crush
  -> SmartCrusher::crush_array
  -> compute_optimal_k
  -> count_unique_simhash

WORKLOAD
Anthropic request with one user tool_result containing a deterministic homogeneous JSON array. Fields match the existing live_zone_dispatch integration fixture: id, status, and repeat-pattern value. Sizes: 200, 1,000, and 5,000 records. Requests were constructed outside Criterion's timed loop.

PREDEFINED ACCEPTANCE RULE
- Exact legacy/candidate output digest, byte length, strategy, and token-count equality.
- p < 0.05 and at least 10% lower central latency at 1,000 and 5,000 records.
- No more than 5% regression at 200 records.
- Do not infer peak memory from Criterion latency.

BASELINE METHOD
The production simhash ASCII condition was temporarily changed from:
  if text.is_ascii()
to the compile-time-false condition:
  if false && text.is_ascii()
This forced ASCII records through the unchanged character-based fallback. Criterion then saved the coding-agent-legacy baseline. The accepted condition was restored immediately afterward, and all 38 adaptive-sizer tests passed before the candidate benchmark ran. The temporary condition is not present in final source.

CANDIDATE COMMAND
cargo bench -p headroom-core --bench adaptive_sizer --no-default-features -- coding_agent_live_zone --baseline coding-agent-legacy

MEMORY ASSESSMENT
Peak memory was not measured. The ASCII path removes Vec<char> construction and one temporary String allocation per 4-gram, so it reduces allocation count and transient allocation traffic by construction. No numeric memory claim is made.

LIMITATIONS
- Criterion compared sequential saved-baseline runs on one Apple Silicon machine, not interleaved process executions.
- The workload is deterministic and matches a real integration fixture shape, but its records are synthetic and homogeneous.
- Only the SmartCrusher JSON-array route was measured. SearchCompressor and LogCompressor also call adaptive sizing but were not tested here.
- Default Criterion timing produced warnings for the 200-record cases, although 100 samples and statistical intervals were still collected.

DECISION
Accept the end-to-end performance claim for this workload. Exact behavior proof passed at every size. Central latency improved 22.0% at 200 records, 21.5% at 1,000 records, and 19.8% at 5,000 records, satisfying every predefined threshold.
