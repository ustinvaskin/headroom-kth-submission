ALGORITHM

Two fingerprints are considered similar when they differ by at most three bits.

Each fingerprint has 64 bits. The prototype splits it into four equal 16-bit parts.

If two fingerprints differ in only three bits, at least one of those four parts
must still be exactly the same. There are four parts but only three changed bits,
so one part cannot have changed.

The prototype stores each group representative under its four parts. For a new
fingerprint, it looks up representatives that share one of those parts, then
runs the normal exact Hamming-distance check only on those candidates.

It still checks candidates in their original order, so it keeps the same
“first matching group” behavior as the original code.

CAVEATS
- Python prototype, not production Rust.
- Fingerprint generation excluded.
- Memory not measured.
- Prototype parity covered deterministic random fingerprints and one-bit near-duplicates, not exhaustive inputs.

DECISION
Promising but not accepted. Establish a production Rust whole-function baseline before changing the algorithm.
