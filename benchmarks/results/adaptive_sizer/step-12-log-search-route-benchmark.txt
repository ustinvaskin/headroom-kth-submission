ADAPTIVE SIZER EXPERIMENT - STEP 12
Date: 2026-09-02
Source: Captured from standard Criterion legacy/candidate route benchmarks after route-harness validation.

GOAL
Measure the final ASCII SimHash implementation through all three production callers of adaptive sizing. Step 7/8 covered SmartCrusher; this step covers the previously unmeasured LogCompressor and SearchCompressor live-zone routes.

ENVIRONMENT
macOS 26.6.2, Apple M4 MacBook Air, 24 GB memory
Rust/Cargo 1.95.0
Criterion 0.8.2 default measurement configuration

WORKLOADS
Each workload is a valid Anthropic request with one `tool_result` block. Requests are constructed outside Criterion's timed loop.

LogCompressor:
- timestamped ASCII build-output lines at 200, 1,000, and 5,000 records;
- a 1,000-record Unicode control using accented Latin and Japanese text.

SearchCompressor:
- ASCII ripgrep-style `path:line:content` matches across ten files at 200, 1,000, and 5,000 records;
- a 1,000-record Unicode control using accented Latin and Japanese text.

The ten-file search fixture stays below the default 15-file cap, so all generated matches reach the adaptive-sizing stage. The harness asserts `Modified`, the expected `log_compressor` or `search_compressor` strategy, and lower output bytes and tokens before timing each case.

COMMANDS
cargo bench -p headroom-core --bench adaptive_sizer --no-default-features \
  --features legacy-simhash-benchmark -- log_compressor_live_zone \
  --save-baseline log-route-legacy
cargo bench -p headroom-core --bench adaptive_sizer --no-default-features \
  -- log_compressor_live_zone --baseline log-route-legacy

cargo bench -p headroom-core --bench adaptive_sizer --no-default-features \
  --features legacy-simhash-benchmark -- search_compressor_live_zone \
  --save-baseline search-route-legacy
cargo bench -p headroom-core --bench adaptive_sizer --no-default-features \
  -- search_compressor_live_zone --baseline search-route-legacy

Criterion reported expected target-time warnings for a few 200- and 5,000-record runs but still collected 100 samples. A small number of outliers were reported. Every ASCII latency interval remained entirely below zero.

INTERPRETATION
The ASCII fast path improves full local compression latency across the SmartCrusher JSON, LogCompressor, and SearchCompressor routes without changing model-visible output. The Unicode controls do not support a speed claim and are consistent with the intended unchanged Unicode implementation.

LIMITATIONS
- Legacy and optimized runs were sequential saved-baseline runs on one Apple Silicon machine.
- Inputs are deterministic synthetic fixtures, not a representative captured log/search corpus.
- This measures Headroom's local routing and compression work, not LLM inference or agent task wall time.
- Peak memory was not measured.

DECISION
Include LogCompressor and SearchCompressor in the final local-compression claim, while keeping the claim scoped to deterministic ASCII-dominant fixtures and preserving the stated limitations.
